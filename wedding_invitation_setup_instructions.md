# Interactive Wedding Invitation --- Setup Instructions

## Project Goal

Create a **standalone, interactive wedding invitation** that can be
shared directly with guests on WhatsApp as a document/file. It should
not require website hosting, a backend, or installation by guests.

The final shareable deliverable should be a single HTML file containing
the experience and its required assets.

## User-Provided Images and Assets

The user must be able to provide images and other assets for the
invitation. Design the project so assets can be added or replaced
easily.

### Images the user may provide

-   Couple photographs
-   Bride and groom portraits
-   Engagement or pre-wedding photos
-   Wedding venue photographs
-   Decorative backgrounds
-   Floral motifs, Bengali alpana, mandala, or other design references
-   Custom envelope or invitation artwork
-   Logos, monograms, or initials

### Development asset folder

During development, support this folder structure:

``` text
wedding-invitation/
├── index.html
├── README.md
└── assets/
    ├── couple-photo.jpg
    ├── bride-photo.jpg
    ├── groom-photo.jpg
    ├── venue.jpg
    ├── background.jpg
    └── decorative/
        ├── floral.svg
        └── alpana.svg
```

These are examples only. Do not assume the user has provided these files
or invent images.

### Asset handling requirements

-   Make it easy for the user or IDE agent to replace images by changing
    filenames or a clearly documented asset configuration section.
-   Use sensible image sizing and cropping (`object-fit`,
    `object-position`) so photos look good on mobile and desktop.
-   Use image overlays where necessary to preserve text readability.
-   Optimize image dimensions and file size.
-   Avoid adding images that the user has not supplied or explicitly
    approved, unless they are simple CSS/SVG decorations generated by
    the project.
-   If the user supplies reference images, use them as visual guidance
    and preserve the requested style.
-   Do not alter supplied photographs unnecessarily.
-   Include graceful fallbacks when an optional image is missing.

### Final standalone HTML

The final file should ideally be self-contained. Before delivery:

-   Embed user-provided images into the HTML using Base64 data URLs, if
    practical.
-   Embed SVG decorations directly in the HTML.
-   Embed audio only if the user provides or approves the audio and the
    resulting file size remains practical.
-   If embedding large assets makes the HTML too large, explain the
    tradeoff and offer a ZIP containing the HTML plus an `assets` folder
    as an alternative. However, the primary requested deliverable is a
    single HTML file.

## Concept

A guest opens the HTML file and sees a royal invitation envelope. They
tap **Open Invitation**, the envelope opens with a smooth animation, and
the invitation card is revealed with wedding details and interactive
buttons.

### Visual Direction

-   Royal Bengali wedding aesthetic
-   Deep burgundy / maroon, antique gold, and ivory palette
-   Elegant serif typography
-   Subtle golden particles and warm ambient lighting
-   Traditional floral / alpana-inspired decorative elements, used
    tastefully
-   Avoid excessive effects; prioritize elegance, readability, and
    performance

## Technical Requirements

Build this as **one self-contained `index.html` file** containing:

-   HTML markup
-   CSS styles
-   JavaScript logic
-   SVG artwork where useful
-   Embedded assets (Base64) in the final file, where practical

Do not require: - React - Vite - Tailwind - Node.js at runtime - A
backend - A database - Hosting or a website URL - External JavaScript
libraries

Prefer native HTML, CSS, and JavaScript. Google Fonts may be used if
available online, but provide elegant system-font fallbacks so the file
still works offline.

## Main Experience / User Flow

### 1. Opening Screen --- Envelope

Show a full-screen mobile-friendly opening scene with:

-   Deep burgundy background
-   Subtle animated golden particles
-   Warm ambient glow
-   A centered elegant envelope
-   Wax seal displaying placeholder initials (e.g. `A & B`)
-   A short line such as "A special invitation awaits"
-   A prominent **Open Invitation** button

The envelope and button should be visually appealing and accessible.

### 2. Envelope Opening Interaction

When the user taps **Open Invitation**:

1.  Button feedback occurs.
2.  Wax seal glows and fades/disappears.
3.  Envelope flap opens using CSS transforms (3D effect if practical).
4.  A warm golden light appears from inside.
5.  Invitation card slides upward/out of the envelope.
6.  The screen transitions to the invitation content.

Use CSS animations and JavaScript state/classes. Keep animations smooth
on mobile devices.

### 3. Invitation Reveal

Reveal the invitation card with:

-   Ivory / cream paper-like background
-   Burgundy and antique gold typography/details
-   Elegant borders and floral/ornamental SVG elements
-   Names of the couple (placeholders initially)
-   Wedding announcement
-   Date and time
-   Venue and address
-   Optional ceremony schedule
-   Optional dress code
-   A personal invitation message

Use tasteful staggered fade/slide animations for text. Ensure text
remains readable and does not become too small on phones.

## Interactive Features

### View Venue

Add a **View Venue** button that opens the exact Google Maps location in
a new browser tab/window.

Use a placeholder URL for now: `GOOGLE_MAPS_PIN_URL`

Eventually replace it with the exact shared Google Maps pin link
supplied by the user.

Use a standard link with `target="_blank"` and
`rel="noopener noreferrer"`.

### RSVP on WhatsApp

Add an RSVP button that opens WhatsApp with a pre-filled message.

Use a placeholder phone number in international format, clearly marked:
`WHATSAPP_PHONE_NUMBER`

The phone number should contain digits only, including country code,
without `+`.

Generate the WhatsApp link using `https://wa.me/PHONE?text=...` and
encode the message.

Example message: "Hello! I would like to RSVP for the wedding
invitation."

### Save the Date

Generate and download an `.ics` calendar file from JavaScript when the
guest clicks **Save the Date**.

Use placeholders for date, time, event title, venue, and description.
Make sure the date/time values are clearly documented and use the
appropriate timezone if known.

### Share Invitation

Add a **Share** button using the Web Share API where supported. If
sharing is unavailable, offer a fallback that copies a message or the
file/invitation description to the clipboard. Explain that sharing a
local HTML file may behave differently across phones, so WhatsApp
document sharing is the intended method.

### Music Toggle (Optional)

Add a visible music toggle, not autoplay. Browser restrictions mean
music should only begin after a user gesture.

If an audio asset is added, embed it or use a relative asset only during
development. For final standalone delivery, ensure it is embedded or
otherwise included with clear instructions. Avoid copyrighted music
unless the user supplies or has permission to use it.

## Effects

Implement optional effects, preferably with CSS/native JavaScript:

-   Golden particles
-   Subtle floating petals
-   Wax-seal glow
-   Envelope flap animation
-   Invitation-card reveal
-   Soft light sweep
-   Button hover/tap feedback
-   Gentle transition between scenes

Keep particle counts low and respect `prefers-reduced-motion`. Provide a
reduced-motion experience for users who prefer less animation.

## Responsive and Compatibility Requirements

-   Mobile-first design
-   Responsive for phone, tablet, and desktop
-   Vertical layout on mobile
-   No horizontal scrolling
-   Large touch targets (ideally at least 44px)
-   High contrast and readable typography
-   Test in Chrome/Edge on desktop and mobile browsers if possible
-   Explain how to open the downloaded HTML file on a phone
-   Do not assume WhatsApp can preview HTML; guests may need to download
    the document and open it in their browser

## Development Approach

Build incrementally:

1.  Create the initial standalone HTML structure and responsive styling.
2.  Implement the envelope and wax-seal design.
3.  Implement the envelope-opening interaction.
4.  Implement the invitation-card reveal.
5.  Add placeholder wedding details.
6.  Add Google Maps, WhatsApp RSVP, and calendar functionality.
7.  Add optional particles, petals, and music toggle.
8.  Integrate any user-provided images/assets and adjust their layout.
9.  Test all interactions and responsive layouts.
10. Check offline behavior and remove unnecessary external dependencies.
11. Embed assets into the final HTML where practical.
12. Deliver the final standalone HTML file and concise instructions for
    sending it through WhatsApp as a document.

## First Task for the IDE Agent

Start by creating `index.html` with the opening envelope scene only. Use
the burgundy, antique gold, and ivory visual direction. Implement a
polished envelope, wax seal with placeholder initials, subtle particles,
and a working **Open Invitation** interaction that reveals a temporary
placeholder invitation card.

Set up an `assets/` folder and make the code ready to accept
user-provided photos and artwork. Include a clearly documented asset
configuration area so supplied images can be incorporated later. Keep
the final output self-contained where practical.

Do not add the actual wedding details yet. First make the opening/reveal
experience look polished and test it.
